   ⚠️ FORM NOTE - READ THIS BEFORE COMPARING TO THE GREENFIELD SCANNERS.
   The greenfield ScannerA/B express the same gate as PLAIN `postagtoday` with the action on the
   **NO** branch. This build uses `postagtoday` + the **`not:true`** flag with the action left on
   the **YES** branch. The two are logically identical (open iff this side was not opened today).
   WHY THE NOT FORM WAS CHOSEN, recorded because it is a deliberate divergence:
     - OA's decision editor edits a node's CRITERIA in place; it has **no move-node control**
       (the node menu is Settings / Precede with / Copy Action / Edit Caption / Edit Notes / Delete).
       Putting the action on NO would have required DELETING the Open Position action and
       REBUILDING it under the NO branch - all of series, both legs, amount, price, filter, tags
       AND the exits bundle.
     - That rebuild would have forced this session to re-author the `exits` field, i.e. to take a
       position on F-C1 (PT25) - the exact question that is gated. The NOT form keeps the action
       node byte-untouched and leaves F-C1 cleanly separable.
     - `not` is a first-class operator on OA's criterion toolbar (Create Group | NOT | delete),
       observed first-hand, not a workaround.
   [FIRST-HAND 2026-08-07: the `oc` token on this recipe offers exactly two values, `opened` and
    `closed`. There is no negated recipe variant, so `not` is the only in-place expression.]

   Everything else in both scanners is UNCHANGED: Loop SPX, the two Range075 symbol-change gates
   (-0.75 / +0.75), FOMC-today, the 11:00am time gate, and both Open actions in full.
