# Roles and ingredients — build map

**What this is.** The living build map for the multi-agent conversion: one row per *thing that has to
exist* — the nine agent roles of `docs/AI Agent Stack.md` §6, the one role that is only proposed, and
the three ingredients every role needs (a trigger, an input, a gate). It answers one question:
**what is actually built, and what is each unbuilt thing waiting on.**

**What this is not.** Not a decision record and not a plan. `docs/build-plan.md` is frozen and nothing
here amends it or any spec. Nothing here amends `docs/AI Agent Stack.md` §6 either — where this file
and the roster disagree about a role's *job*, the roster wins; this file only tracks its *state*.
Sequencing for the Devin lane lives in `docs/devin-queue.md` (PR #2, merged `c9de1e3`), and phase entry/exit
criteria in `docs/AI Agent Stack.md` §8. Where a status is numeric, the named command produces it and
the command's output wins.

**Kind.** *code* = deterministic script, no model in the loop. *agent* = a model reading and
proposing. *orchestrator* = the single writer that dispatches and applies ruled changes.
*ingredient* = not a role at all, but a precondition several roles share.

**Owner.** *Andy* = rulings, tokens, repo settings — anything only the human can sign or enable.
*Cowork* = the Claude session (`.claude/`) that reads, proposes, and drafts. *Devin* = the PR lane:
code, CI, wiring. Owner is who moves the row next, not who eventually maintains it.

## How to read the map

**One row is unblocked by a merge, not by work.** Row 13 is green and sitting in a PR. Rows 2, 9 and
11 name it as their blocker, and rows 1 and 6 sit behind it too. The cheapest move on this map is a
merge and a settings toggle, not a build.

**Four rows are blocked on rulings, not code** — rows 4, 8, 10 and 12 (all three gaps). Devin can
propose every one of them and can implement none of them unilaterally. Rows 8 and 12(b) are the
narrowest: each is a single signature away from a stage running clean.

**The two frozen deterministic scripts are the assets.** Row 3 is 21/21 and row 6's intended form is
CI, not an agent. `scripts/execution_audit.py` and `scripts/comparative_machinery.py` stay
model-free — that is what makes their output admissible as evidence.

**Refusals are passes.** Row 4 refusing to grade below n≥100, row 8 refusing to truncate the v1
index, row 3 reporting `SKIPPED` rather than a silent pass, row 2 halting on a missing input — each is
the system working. A row that starts inferring past a missing input is a regression, not progress.
